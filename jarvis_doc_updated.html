Project Summary

Jarvis is a local-first Windows assistant designed for production runtime stability. The repo is structured around a streaming voice pipeline, layered command routing, graceful fallback paths, and safety-aware OS actions.

  • Wake word to response flow is optimized for low-latency command execution.
  • Arabic and English are both supported across STT, routing, voice controls, and fallback handling.
  • LLM usage is local-first through Ollama, with Claude support available as an alternate backend.
  • Windows-specific features include app control, file operations, system actions, search, clipboard, and policy gating.

Architecture

A layered runtime: capture, route, execute, speak, and log. The document below reflects the current file layout visible in the repo.

Primary layers

  • audio/ handles microphone capture, wake word, VAD, STT, TTS, and barge-in.
  • core/ contains orchestration, parsing, routing, metrics, diagnostics, config, session memory, and handlers.
  • llm/ manages prompt building and local / cloud model client logic.
  • nlp/ provides semantic routing and supplementary intent recognition paths.
  • os_control/ contains action execution, policy, confirmations, file ops, system ops, and persistence helpers.
  • tools/ provides live data and search integrations used by the router.

Operating model

  • Preferred path: deterministic parser and action handlers.
  • Fallback path: semantic router or keyword classifier.
  • Last resort: LLM-backed conversational handling.
  • Safety path: language gate, confirmation, second factor, policy checks, and rollback logging.

Runbook

  • Install: python -m pip install -r requirements.txt
  • Start app: python main.py
  • Health check: python core/doctor.py
  • Deep diagnostics: python core/doctor.py --full
  • Demo mode: python main.py --demo-mode

Configuration Highlights

  • JARVIS_LLM_MODEL selects the model override.
  • JARVIS_LLM_AUTO_SELECT enables hardware-aware model selection.
  • JARVIS_WAKE_WORD_AR_ONNX_PATH enables Arabic wake-word support.
  • JARVIS_STT_BACKEND switches between local and hybrid STT modes.
  • JARVIS_TTS_BACKEND controls the speech backend policy.
  • DOCTOR_STARTUP_ENABLED and DOCTOR_SCHEDULE_INTERVAL_SECONDS govern diagnostic cadence.

Workspace hygiene

Keep generated logs and transient caches out of version control. The repo already contains runtime artifacts such as log and DB files in the workspace; only commit the actual source and documentation changes you intend to keep.
